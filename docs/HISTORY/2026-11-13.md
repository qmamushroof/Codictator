## 2026-11-13 · fix(workflow): reclassify a docs task that touches code as code
- **Kind:** code
- **Task:** T-0028
- **Bug:** BUG-0087
- **Why:** SPEC §4.12.2 says a change that touches code files is reclassified as code and owes every gate, but checkPhaseGate judged only the declared task.type, so a docs-typed task whose plan writes code skipped the red and green proofs; the planning and validation gates now apply classifyChange to files.allow and waive the proofs only while every planned path is a docs path.
- **What went wrong:** nothing abandoned; the existing docs-class gate test used a docs task with src/** in files.allow, which contradicts the SPEC, so its fixture now allows docs/** only.
- **Trade-offs:** the class is judged from the planned files.allow globs, not from the staged files at advance time; a write outside the plan is already blocked by core/writes-within-plan, so the plan is the one source.
- **Lessons:** classifyChange takes glob strings as paths, so a glob such as docs/** or **/*.md classes as docs only when it starts with docs/ or ends in .md; a broad glob such as ** counts as code.
