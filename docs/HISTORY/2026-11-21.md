## 2026-11-21 · fix(hooks): commit-msg honours the merge-commit exemption
- **Kind:** code
- **Task:** T-0059
- **Bug:** BUG-0079
- **Why:** commit-msg judged a merge commit like a normal one, so the merged branch's own history entry, staged against the first parent, counted as added by the merge and blocked it despite the SPEC §4.9.3 exemption; the hook now detects a merge in progress through MERGE_HEAD and skips the history judgement, keeping the trailer append.
- **What went wrong:** nothing notable; the first acceptance draft passed only because a guessed hooksPath setting disabled the installed hook, so the test now relies on the hook install alone.
- **Trade-offs:** the exemption keys on MERGE_HEAD, so a squash or fast-forward merge, which leaves none, is judged as an ordinary commit, which matches the never-squash rule of SPEC §4.9.3.
- **Lessons:** an acceptance test that can pass without the hook running proves nothing, so confirm it fails first with the hook live.
