# 11. Decisions

**[◀ 10. Testing Strategy](10-TESTING-STRATEGY.md)** · [SPEC index](../SPEC.md) · **(last)**

Implementation decisions made while writing the SPEC. Product decisions live in PRD §12; an `S#` never contradicts one. Ids are append-only; a reversal rewrites the entry with its new reason. *Founder* marks a founder decision recorded here because it is implementation-level.

| # | Decision | Reason | Rejected |
|---|---|---|---|
| S1 | **npm workspaces, two packages:** `codictator` (engine, built-in packs, adapters, CLI) and `codictator-vscode` (§3.1) | One engine and one version per repo; packs ship with the engine so `config.codictator` names the whole rule set | One package per pack or adapter — version skew between packs and engine |
| S2 | **Zero runtime dependencies** (§2.2) | Smallest attack surface for a tool installed into many repos (PRD §11.8) and platform first (PRD §6 P7) | ajv, commander, execa, globby — each replaced by a platform API or a small kernel utility |
| S3 | **`node:test` on source via type stripping; no bundler** | No test-runner dependency; no build before tests | Vitest, Jest |
| S4 | **TypeScript 7.0.2 is used only as the `tsc` CLI** | 7.0 ships no stable JS API; nothing in Codictator or its enforcement needs one | Staying on TypeScript 6 for the API |
| S5 | **Own lexer-based import graph for every language** (§4.11) | One uniform engine, fast enough for L1 single-file checks, no per-language tool to install | dependency-cruiser, import-linter, NetArchTest (three tools, three configs, too slow per edit) |
| S6 | **The extension uses the repo-pinned engine over stdio**; CommonJS shim + ESM main; `engines.vscode ^1.105.0` (§4.20) | One verdict regardless of surface (PRD §12 #2); the shim works on VS Code 1.105, which Cursor bundles | Bundling an engine copy (version skew); ESM-only entry (needs a newer VS Code than Cursor ships) |
| S7 | **JSON for every Codictator file**, with JSON Schemas | No parser dependency; schema validation; stable diffs | YAML, TOML, JSONC |
| S8 | **Biome** lints and formats Codictator itself | One dependency for two capabilities | ESLint + Prettier (two capabilities, many transitive packages) |
| S9 | **Security-release exemption from the minimum release age** (§4.8.3) | Without it the age rule holds a repo on a known-vulnerable version, contradicting PRD §12 #15 | Waiting out the age while vulnerable |
| S10 | **`config.codictator` pins the engine; mismatch blocks** | Every surface and machine evaluates the same rule set | Floating engine versions |
| S11 | **A waiver may be renewed once; the chain ends at 2 × `maxWaiverDays`** | Gives a real second chance while keeping exceptions temporary (PRD §12 #16) | Unlimited renewals (a permanent loosening) |
| S12 | **A floor finding already on the base branch blocks every PR except one that fixes it** (§4.13.8) — *Founder* (PRD §12 #35) | Keeps "no mercy" on the floor while letting a multi-step fix land in safe steps (PRD §12 #31) | Blocking fix PRs too (deadlock); allowing all PRs (floor escape) |
| S13 | **Floor rules may be ratchet-capable** (§5 column R) | PRD §7.8 baselines brownfield debt; "floor" still means no waiver and no off switch, and the count only falls | Treating every floor violation as an immediate block (permanently red brownfield builds, PRD §11.11) |
| S14 | **Muse Code L1 denies only via exit 0 + `hookSpecificOutput.permissionDecision: "deny"`; allow is `{}`; never exit 2, `updatedInput` or post-tool blocking** (§4.5.4) — *Founder* | The only reply shape live probes agree on; the rest is unconfirmed or contradictory, and git hooks plus CI back it up. `hookIoVerified` stays false until a first-party capture | Claude-style exit 2 (unconfirmed for Muse); waiting for vendor docs (no L1 for the P0 harness) |
| S15 | **Muse Code project memory carries a steering pointer** | It loads before workspace trust, unlike `AGENTS.md`, so L0 exists from the first prompt | Relying on `AGENTS.md` alone |
| S16 | **One external-tool contract, add-only** (§4.4.5) — *Founder* (PRD §12 #32) | Users can plug in any tool while the floor and bounds stay untouchable | Per-tool integrations; letting tools replace built-in enforcers |
| S17 | **Node.js LTS is a prerequisite in every target repo; no standalone binary; minimum checked with `CDX-E001`/`E002`** (§4.19.4) — *Founder* (PRD §12 #33) | One runtime for every surface | Single-file executables per OS |
| S18 | **Reviewer identity comes from the hook's recorded shell event; without L1 it is declared and flagged** (§4.12.4) | Freshness must be checked by data, not by the reviewer's word (PRD §12 #26) | Trusting a `--session` flag everywhere |
| S19 | **`--no-verify` is detected by a commit trailer added at `commit-msg`** (§4.14.2); a commit without it blocks at L4 unless its author is exempt — *Founder* (PRD §12 #35) | Makes a bypassed local layer visible at L4 (PRD §5.3) | Undetectable bypass |
| S20 | **Red proofs use JUnit/TRX reports and are re-run by CI in a worktree** (§4.10.2) | A test that never ran is not red; an edited record cannot fake it | Trusting the recorded proof |
| S21 | **History is monthly Markdown under `docs/HISTORY/`, one entry per commit; CI appends bot entries** (§4.9.3, §4.15.3) | Readable by agents and humans; append-only check is a prefix test | One file per change (folder breadth), JSONL (unreadable in review) |
| S22 | **Only GitHub Actions is generated in the first release**; other CI runs one command and is shown as unverified (§4.15.6) — *Founder* (PRD §12 #36); GitLab CI later | The git-host API is also needed for required-check and PR features | Generating for every CI host now |
| S23 | **Generated packs use only parametric enforcers** (§4.16) | An LLM never authors executable enforcement code | Generated `.mjs` enforcers |
| S24 | **Default LLM preset is Meta `muse-spark-1.3` over Chat Completions; never a contributor variant** (§4.17) | Meta-first default (PRD §12 #30) without training on user content | Contributor variants as default (cheaper but used for training) |
| S25 | **Human-only commands need a TTY and no agent markers** (§4.2.3) | Waivers, acceptance and acks must come from a person (PRD §6.1) | Confirmation prompts an agent can answer |
| S26 | **Remediation: one step, one PR; Codictator executes only mechanical steps** (§4.13) | Small verified steps keep the app working (PRD §12 #31) without Codictator writing feature code (PRD §12 #23) | Batched cleanup PRs; Codictator refactoring code itself |
| S27 | **Default thresholds** — source file 300 lines, function 40, cyclomatic 10, doc leaf 40 KB, minimum release age 7 days, lag 30/60 days, coverage 90/80 (§5) | Strict enough to keep files and context small, loose enough to be met by clean code without contortion | Stricter defaults that force artificial splitting; looser ones that let bloat in |
| S28 | **Names: npm package `codictator`; VS Code Marketplace and Open VSX publisher `codictator`, extension id `codictator.codictator-vscode`** (§3.2) — *Founder* (PRD §12 #37) | One name everywhere; both npm names were unclaimed on 2026-10-26 | — |
| S29 | **OpenCode L1 is a generated plugin bridge that spawns the launcher and throws on block** (§4.5.4) | OpenCode has no command hooks; a plugin is its documented blocking point, and owning both sides of the wire makes it fail closed | A TypeScript plugin importing `@opencode-ai/plugin` (a dependency in the target repo) |
| S30 | **The launcher embeds each configured harness's static block reply** (§4.5.1) | A missing engine or old Node must block in the harness's own deny form; exit 2 is not a universal deny (Muse Code) | One exit code for every harness |
| S31 | **OpenCode per-prompt context: `chat.message` computes, `experimental.chat.system.transform` delivers before every model call; a synthetic `chat.message` part is the probed fallback** (§4.5.4) | Both hooks exist in `@opencode-ai/plugin` 1.15–1.19.4; the transform reaches every loop step and subagent without growing history, and the fallback keeps injection alive if the experimental hook disappears; injection never throws, gating stays at `tool.execute.before` | `chat.message` part alone (persists in history, misses later loop steps); `experimental.chat.messages.transform` (rewrites the whole history); `chat.params` (no text field); an owned `instructions` file (static, duplicates `AGENTS.md`) |
| S32 | **The OpenCode adapter supports `>=1.15.0 <2.0.0`; 2.x is a declared gap until a 2.x release has been npm `latest` for at least 7 days and a first-party capture passes** (§4.5.4) — *Founder* | Every hook the bridge uses exists across 1.15–1.19; 2.x reshapes the plugin API, and the 7-day age matches the release-age default | Claiming 2.x support from unreleased tags |
| S33 | **Merges never squash, on Codictator's repo and in every target repo: merge commit or rebase only; `core/branch-protection` checks the host setting** (§4.9.3, §4.15.2) | One history entry per commit survives only if commits and subjects survive the merge | Squash merges with a rewritten entry (the entry no longer matches any commit) |
| S34 | **Codictator's own red-first tests stay green on `main` through the red ledger** (§10.7) | Lets the whole suite be written up front while every merge stays green, with no skip marker and no lenient expected-failure | Skip markers until implementation; a long-lived red branch |
| S35 | **Secret detectors live in the kernel as `redactSecrets`; `security` owns their definition** (§4.1.2, §4.7.1) | The engine, audit and adapters must redact, and §3.3 forbids them to import `security` | Redaction only inside `security` enforcers (misses other findings and raw payload logs); letting the engine import `security` |
