# 4.15 ci

**[◀ 4.14 integrity](04-14-INTEGRITY.md)** · [SPEC index](../SPEC.md) · **[4.16 generator ▶](04-16-GENERATOR.md)**

Generates and checks the merge gate (PRD §6 P6, §8 F13). First release generates GitHub Actions only (PRD §12 #36); any other CI runs the same command (§4.15.6).

## 4.15.1 Generated workflow

`.github/workflows/codictator.yml`, manifest-owned:

| Element | Value |
|---|---|
| Triggers | `push` to the default branch, `pull_request`, `schedule` (daily, minute and hour derived from a hash of the repo name to spread load), `workflow_dispatch` |
| Permissions | Workflow default `contents: read`; jobs raise only what they need |
| Concurrency | `codictator-${{ github.ref }}`, cancel in progress for PRs |
| Actions | `actions/checkout` and `actions/setup-node`, each pinned by full commit SHA with the version as a trailing comment, resolved at generation by latest stable (§4.8.3) |
| `verify` job | Checkout with `fetch-depth: 0` and `persist-credentials: false`; setup Node from `.nvmrc` (or `.codictator/tool/.nvmrc`); `npm ci --ignore-scripts` (root or tool dir); `codictator ci verify`; runs-on each OS in `config.ci.os` (default `ubuntu-latest`; adding OSes is tightening) |
| `record-bot-change` job | PRs from same-repo branches authored by a recognised bot: `contents: write`; appends the history entry commit (§4.15.3) |
| `sweep` job | Schedule only (§4.15.4); `contents: write` and `pull-requests: write` only when no bot is configured |

`codictator ci verify` reads base and head from `GITHUB_EVENT_PATH` (PR base SHA, or `before` for pushes), evaluates `ci.verify` (§4.3.2), re-runs red proofs (§4.10.2), writes the summary to `GITHUB_STEP_SUMMARY` and exits per §8.

## 4.15.2 Checks

| Rule | Check |
|---|---|
| `core/ci-present` | The workflow exists and matches the manifest; `verify` job present with the generated steps |
| `core/ci-required-check` | Default branch requires the `verify` check: read rulesets via `GET /repos/{owner}/{repo}/rules/branches/{branch}`, then classic protection when readable. **Reported not required → block. Unreadable → advise** in the summary (PRD §11.1) |
| `core/branch-protection` | Same sources plus `GET /repos/{owner}/{repo}`: force-push and deletion blocked on the default branch, and squash merging disabled (§4.9.3) by `allow_squash_merge: false` or by a ruleset's `allowed_merge_methods` without `squash`; same unreadable handling |
| `core/ci-actions-pinned` | Every `uses:` in every workflow is a 40-hex SHA; every `container`/`services` image is digest-pinned |
| `core/perf-budgets` | When any test declares a budget (§4.10.3), `config.commands.perf` exists and the generated `verify` job runs it |

## 4.15.3 Bot dependency changes

A PR qualifies when its commits only touch manifests and lockfiles and its author is a recognised bot (`renovate[bot]`, `dependabot[bot]`, plus `config.integrity.trailerExempt`). For it, `codictator ci record-bot-change` appends one commit to the PR branch with the `deps` history entry derived from the diff (package, from, to, advisory ids fixed, release-age). Fork PRs are never written to; their entries are required as usual. The verdict on the PR is Codictator's, never the bot's (PRD §12 #28).

## 4.15.4 Scheduled sweep (L5)

`codictator ci sweep`: full `schedule.sweep` evaluation with fresh registry data; ratchet report; upgrade PRs when no bot exists (§4.8.7); `remediate plan` refresh. Changes to committed state (plan, tightened baseline) go to a single PR `codictator/sweep` updated in place, never to the default branch. A sweep that finds a new floor finding on the default branch (e.g. a fresh advisory) fails, making the escape visible (PRD §10 north star).

## 4.15.5 Codictator's own pipeline

Codictator's repo runs this same generated workflow (PRD §6 P11) plus a test matrix on Ubuntu, Windows and macOS (§10). Its release workflow runs from tags only, after a full verify (§9.2). It publishes `codictator` with npm trusted publishing (OIDC) and provenance, and the extension with `vsce` and `ovsx`.

## 4.15.6 Other CI hosts

`config.ci.host: "external"` skips workflow generation; `init` prints the one command to run (`npx --no-install codictator ci verify --base <sha> --head <sha>`) and requires the human to confirm it is wired as a required check. `core/ci-present` then checks only the confirmation record and reports the gate as **unverified** everywhere.

## 4.15.7 Edge cases

| EC | Case | Expected |
|---|---|---|
| EC-1 | PR from a fork (read-only token) | `verify` runs; required-check rule advises if unreadable |
| EC-2 | Shallow clone despite config | `CDX-E503`: base not reachable, block |
| EC-3 | Push of a new branch (no `before`) | Base = merge-base with default branch |
| EC-4 | Workflow edited to add `continue-on-error: true` | Manifest drift, block |
| EC-5 | Another workflow uses `actions/checkout@v4` | Block `core/ci-actions-pinned` |
| EC-6 | Branch protection API returns 403 | Advise "cannot confirm required check" |
| EC-7 | Ruleset exists but `verify` not in required checks | Block |
| EC-8 | Bot PR from a fork | No commit written; entry required |
| EC-9 | Sweep PR already open | Updated in place; never a second |
| EC-10 | Scheduled run on a repo with no changes | Still evaluates fresh advisories |
| EC-11 | Repository allows squash merging and no ruleset excludes it | Block `core/branch-protection`; remediation names both settings |
