# 4.17 llm

**[◀ 4.16 generator](04-16-GENERATOR.md)** · [SPEC index](../SPEC.md) · **[4.18 audit ▶](04-18-AUDIT.md)**

A provider-agnostic completion client used only by the generator (§3.3 boundary; PRD §12 #3, #19, #30). Optional: every other feature works with no LLM configured.

## 4.17.1 Configuration

`config.llm` (§7.2): `provider` (preset id), `baseUrl`, `format`, `model`, `apiKeyEnv` (the **name** of an environment variable; literal keys are rejected, `CDX-E106`), `timeoutMs`, `maxOutputTokens`, optional `reasoningEffort`.

| Preset | `baseUrl` | `format` | `model` | `apiKeyEnv` |
|---|---|---|---|---|
| `meta` (default suggestion) | `https://api.meta.ai/v1` | `openai-chat` | `muse-spark-1.3` | `MODEL_API_KEY` |
| `meta-messages` | `https://api.meta.ai/v1` | `anthropic-messages` | `muse-spark-1.3` | `MODEL_API_KEY` |
| `openai-compatible` (local Llama or Muse Spark Open via Ollama, vLLM, llama.cpp, or any host) | user-set, e.g. `http://127.0.0.1:11434/v1` | `openai-chat` | user-set | optional |
| `anthropic` | `https://api.anthropic.com/v1` | `anthropic-messages` | user-set | `ANTHROPIC_API_KEY` |
| `openai` | `https://api.openai.com/v1` | `openai-chat` | user-set | `OPENAI_API_KEY` |

Defaults never select a `-contributor` model variant, because those may be used for training (PRD §6 P8). `init` offers the `meta` preset first; no preset depends on Meta's retired hosted Llama API (PRD §12 #19).

## 4.17.2 Wire formats

| Format | Request | Response read |
|---|---|---|
| `openai-chat` | `POST {baseUrl}/chat/completions`, `Authorization: Bearer`, `messages` with a `developer` (or `system`) message, `response_format: { type: "json_object" }` when supported, `reasoning_effort` when set (never `none` for Muse Spark, which rejects it) | `choices[0].message.content` |
| `anthropic-messages` | `POST {baseUrl}/messages`, `x-api-key` and `anthropic-version` headers (Meta: Bearer), `system` + `messages`, `max_tokens` | concatenated `text` content blocks |

`temperature: 0` is sent where accepted. The client returns `Result<{ text, usage? }>`; it never throws.

## 4.17.3 Network and privacy

The configured `baseUrl` host is added to the net allowlist for the generator's process only (§9.2); a loopback host is allowed for local runtimes. Keys are read from the environment at call time and never logged, cached or written. Requests and responses are not stored; the event log records provider, model, byte sizes, duration and status only.

## 4.17.4 Edge cases

| EC | Case | Expected |
|---|---|---|
| EC-1 | `apiKeyEnv` variable unset | `CDX-E852` naming the variable |
| EC-2 | 401/403 | `CDX-E852`, key not echoed |
| EC-3 | 429 or 5xx | Retry ×2 with 2 s and 8 s backoff, then `CDX-E854` |
| EC-4 | Timeout | `CDX-E854` |
| EC-5 | `baseUrl` uses `http://` on a non-loopback host | `CDX-E106` (keys over plaintext refused) |
| EC-6 | Provider rejects `response_format` | Retried once without it |
| EC-7 | Response truncated at `maxOutputTokens` | Treated as invalid JSON → generator repair round |
