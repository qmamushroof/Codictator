# 4.19 cli

**[◀ 4.18 audit](04-18-AUDIT.md)** · [SPEC index](../SPEC.md) · **[4.20 extension ▶](04-20-EXTENSION.md)**

The composition root: wires ports into modules and exposes every surface — commands, the hook entry point, the launcher, and the stdio server for the extension (PRD §7.1, §12 #2).

## 4.19.1 Conventions

`codictator <command> [subcommand] [flags]`, parsed with `node:util.parseArgs` (unknown flag → exit 2). Global flags: `--json` (machine output, schema per command in `schema/cli/`), `--cwd <path>`, `--quiet`, `--help` (print usage, exit 0). Human output is terse: one line per finding — `rule  path:line  message` — then the `Do instead` line. Exit codes are §8.2. Verify scopes exclude pack fixture dirs (§4.4.1): fixtures are rule test data, judged by `pack test` and the red suite.

## 4.19.3 Hook entry and launcher

**Launcher** `.codictator/bin/run.mjs` is manifest-owned and a plain ES2017 module, so any Node can parse it. It checks the Node version (§4.19.4), then resolves the engine at `<root>/node_modules/codictator/dist/cli/main.js`, else `<root>/.codictator/tool/node_modules/codictator/dist/cli/main.js`. It reads the resolved engine's manifest version and passes it as `main`'s third argument, so hook and git-hook validation see the installed engine version (§4.2.1 EC-11); an unreadable manifest falls back to the two-argument call, which keeps the pinned placeholder. If neither exists, it emits the harness's embedded static block reply for `CDX-E003` ("run npm ci", §4.5.1); outside `hook` it prints `CDX-E003` and exits 6. For `hook` invocations it sets `CODICTATOR_HOOK=1` in the engine process.

**Hook runtime** (`hook <harness> <event>`), in order:

1. Start the time limit (§4.5.5); read stdin to EOF, cap 8 MiB (`CDX-E305`).
2. Resolve the repo root from the payload `cwd` or process cwd via `git rev-parse --show-toplevel`; outside a Codictator repo → allow silently (§4.2 EC-2).
3. Load `EffectiveConfig` from `.codictator/cache/effective.json` when its key (hashes of config, waivers, baseline, pack versions) matches, else resolve and cache (§4.2.1).
4. `adapter.parse` → `HookEvent`; map to a trigger (§4.3.2); import only the modules that trigger needs.
5. `engine.evaluate`; then the loop breaker (§4.12.5) and steering injection (§4.6.3).
6. `adapter.reply` → stdout, stderr, exit code. Any uncaught error → block with `CDX-E901`; time limit reached → block with `CDX-E902`.

## 4.19.4 Node prerequisite (§11 S17)

Node.js LTS is required in every target repo, including .NET and Python repos; there is no standalone binary. The minimum is the installed engine's `engines.node` (`>=24.0.0`, §2.3).

| Where checked | Missing | Too old |
|---|---|---|
| Git hooks (`sh`, before invoking node) | `CDX-E001`, exit 1 | `CDX-E002`, exit 1 |
| Launcher | n/a (harness cannot start it: the adapter's declared `launcherMissingFailMode` applies, and the next git hook or CI run blocks) | `CDX-E002` as the harness's static block reply (§4.5.1) |
| CLI start | n/a | `CDX-E002`, exit 6 |

**Install location.** npm repos pin `codictator` as an exact root `devDependency`. Other repos get `.codictator/tool/package.json` and `package-lock.json` pinning it, installed with `npm ci --prefix .codictator/tool` into a git-ignored `node_modules`, so no root `package.json` is imposed.

## 4.19.5 Stdio server

`serve --stdio` speaks newline-delimited JSON-RPC 2.0 (protocol §7.15) for the extension. It exposes read methods and a `run` method that executes CLI commands under the same rules. A human-only command is answered with `CDX-E107` and the exact command line, so the extension can open a terminal for the human (PRD §12 #22). It watches the event log and pushes `events/appended` notifications. Verdict appends through `run` follow §4.18.1.

## 4.19.6 Setup orchestration

`usage: codictator setup [--harness <id> ...] [--profile <app|library|cli|service>] [--pack <id> ...] [--tool <role>=<command>@<pin> ...] [--repair]`. Human-only (§4.2.3). Flags mirror `init` (§4.19.2); any positional is a usage error. `setup` runs adoption end to end, then hands the repo to the extension (§4.20.1):

| Step | What runs | Owner |
|---|---|---|
| 1. Preflight | Node prerequisite check | §4.19.4 |
| 2. Init or repair | The adoption sequence (§4.13.1) | §4.13.1 |
| 3. Gitignore | Manifest-owned ignore entries | §7.1 |
| 4. Place engine | Write the engine dependency per the repo kind, without installing | §4.19.4 |
| 5. Install engine | Run `npm ci` in the directory owning the lockfile | §4.19.4 |
| 6. Hooks | Git hooks written and `core.hooksPath` pointed at them | §4.14.4 |
| 7. Verify | First evaluation over the adopted repo | §4.19.2 |
| 8. Extension handoff | Views connect once a config exists | §4.20.1 |

Tool-scope installs need consent. When `.codictator/tool/package.json` or the tool lockfile is missing, setup prompts the TTY human with `y/n`, naming the missing artifact, the directory and the exact command. `y` writes the manifest and runs `npm install` then `npm ci` in `.codictator/tool`, anything else fails closed with `CDX-E003` without mutating the repo. A non-TTY run fails the same way without prompting. The root scope never prompts: a missing root lockfile is `CDX-E003`. A consented install that hits a registry or network outage fails with `CDX-E401`.

A step failure stops the run with the exit code in the table below (§8.2). With `--json`, `setup` reports one result object per step; the shape is owned by `schema/cli/` (§4.19.1).

| Failure | Exit |
|---|---|
| Unknown flag or positional | 2 (EC-1) |
| Config invalid after the init path | 3 |
| No TTY or agent markers present | 4 |
| Registry or network unavailable during install | 5 |
| Node or engine prerequisite missing | 6 |

Step 8 owns the empty-packs warning: when the effective pack list is empty it prints "Setup complete — core rules only. No language packs installed.", "To add a language pack, run exactly one line and press Enter:", "  npx codictator setup --repair --pack typescript" (fresh adoption omits --repair: "npx codictator setup --pack typescript"), "To install the VS Code extension, run:" and "  code --install-extension codictator.codictator-vscode".

## 4.19.7 Edge cases

| EC | Case | Expected |
|---|---|---|
| EC-1 | Unknown command or flag | Exit 2 with usage line |
| EC-2 | `--json` on a human-only command from a non-TTY | `CDX-E107` as JSON |
| EC-3 | Hook invoked with an unknown harness id | Block `CDX-E301` |
| EC-4 | Hook stdin empty | Block `CDX-E303` |
| EC-5 | Node 22 on PATH | Git hooks and launcher print `CDX-E002` with the required version |
| EC-6 | Both root and tool-dir engines installed at different versions | `CDX-E102`; root wins only when it equals `config.codictator` |
| EC-7 | Effective-config cache stale after a waiver edit | Key mismatch → re-resolved |
| EC-8 | `verify` outside a git repo | `CDX-E703` |
| EC-9 | Server receives malformed JSON-RPC | JSON-RPC parse error response; server keeps running |
| EC-10 | Two servers on one repo (two VS Code windows) | Both work; log appends are line-atomic |
