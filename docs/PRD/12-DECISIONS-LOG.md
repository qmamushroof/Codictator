# 12. Decisions Log

**[◀ 11. Risks & Mitigations](11-RISKS-MITIGATIONS.md)** · [PRD index](../PRD.md) · **[13. Open Questions ▶](13-OPEN-QUESTIONS.md)**

Load-bearing product decisions. **Recorded, do not re-litigate.** Ids are append-only and never reused; a reversal rewrites its entry in place with the new reason. *Founder* = decided by the founder; *PRD* = decided while writing this PRD, open to founder veto via §13.

| # | Decision | Reason | Source |
|---|---|---|---|
| 1 | **Generate + guard.** Codictator installs a deterministic harness into the target repo — per-harness hooks and config, context files, git hooks, CI, lint/architecture/test/doc guards, dependency enforcement — and runs continuous checks that block bad changes. Its context and guards make the agent do the right thing, transparently, rather than merely refusing prompts. | Prompt refusal is bypassable; enforcement on the produced change is not. | Founder |
| 2 | **Core is a TypeScript CLI/engine on npm; the VS Code extension is a thin client over it**, showing live what is enforced, how the LLM is steered, violations and history. | One engine means one verdict regardless of surface. | Founder |
| 3 | **Codictator's own LLM is optional** — bring-your-own key or local model, used only for non-core features such as the guardrail generator. Meta models are first-class (default per #30); any provider works. Dependency checks use registries and advisory data, never an LLM. | Enforcement must stay deterministic and free to run. | Founder |
| 4 | **Pluggable packs.** Language-agnostic rules apply to any repo. First-release language packs: TypeScript/JavaScript first, then .NET, then Python. | Breadth without forking the engine. | Founder |
| 5 | **Codictator's codebase:** latest stable TypeScript, minimal or no frameworks unless strongly justified, feature-based clean modular monolith, evolutionary architecture; it follows everything it preaches. | Credibility and a small attack surface. | Founder |
| 6 | **Single- and multi-agent workflows both supported.** Default: discovery → planning → implementation → validation → pre-commit review → record changes → commit, push, merge. Customisable within reason; never dumbed down; always transparent. | Matches how agent-only teams actually work. | Founder |
| 7 | **Codictator is itself built SPEC-driven ATDD**: failing tests and guardrails written upfront, then implementation. | Dogfoods F4 from the first line. | Founder |
| 8 | **Two tiers: floor and tunable.** Floor rules have no waiver; tunables tighten freely and loosen only within bounds with reason and expiry (§6 P2, §6.1). | Gives decision 6's "reasonable requests" a decidable definition. | PRD |
| 9 | **A rule needs an enforcer and a violating fixture**, with a test proving it is caught (§6 P3). | An unproven enforcer is trusted while detecting nothing. | PRD |
| 10 | **CI is the source of truth**; local layers are early feedback (§6 P6). | Every local layer can be bypassed; the merge gate cannot without visible admin action. | PRD |
| 11 | **Local and private.** No account, server or telemetry; network limited to registries, advisory databases, the repo's own git host and a user-configured LLM (§6 P8). | Trust and adoptability. | PRD |
| 12 | **Fail closed.** An enforcer that errors, times out or lacks data blocks with an explanation (§7.1). | A guard that passes on error is disabled by any error. | PRD |
| 13 | **Brownfield via ratchet; improvement via the normal workflow.** Debt is baselined and may only fall; Codictator's improvements arrive as visible, reviewed, incremental changes that keep the app working (#31), never silent edits (§7.8). | A permanently red build gets switched off; silent edits break transparency. | PRD |
| 14 | **"Latest stable" =** newest non-prerelease version, older than a minimum release age, with no known advisory, compatible with the declared runtime. The age value is SPEC-owned and tunable within bounds. | Compromised releases are typically caught and pulled within days; a short age blocks them without meaningful staleness. | PRD |
| 15 | **Vulnerable or deprecated versions have zero allowance; merely outdated ones get an upgrade change plus a bounded, tunable lag allowance** (§7.5). | Founder's "no mercy" on vulnerabilities, without blocking all work the day a new major lands. | Founder |
| 16 | **Waivers** exist only for tunable rules, need a reason and an expiry, and are shown in the CLI, extension and CI summary until they lapse. | Visible exceptions stay exceptions. | PRD |
| 17 | **Loop breaker.** Repeated blocks on the same rule in one task stop the attempt and escalate to the human (§7.1). | Caps token burn without lowering the floor. | PRD |
| 18 | **Capability honesty.** Each adapter declares what its harness can enforce; gaps are shown and covered by lower layers, never claimed (§7.3). | Overclaiming enforcement is worse than admitting a gap. | PRD |
| 19 | **LLM access is provider-agnostic and covers Meta's open-weight and hosted models.** Hosted Muse models via the Meta Model API (OpenAI- and Anthropic-compatible formats); open-weight Muse Spark Open and Llama via a local runtime or any OpenAI-compatible host; any other closed Meta model wherever an endpoint exists. Meta's hosted Llama API preview was retired on 2026-07-06. | "Meta models" means every Meta model a user can reach, and no default may depend on a retired endpoint. | Founder |
| 20 | **Generated guardrails are deterministic artifacts** (rule, enforcer, fixtures), inert until they pass their self-test and a human accepts them (§7.9). | Keeps the LLM out of every enforcement path. | PRD |
| 21 | **First-release adapters:** Muse Code, OpenCode, Universal, Claude Code, GitHub Copilot and Codex CLI at P0; Cursor and Gemini CLI at P1 (§9.1). OpenCode is P0 because Codictator dogfoods itself in OpenCode with Meta models via the Meta Model API; its provider setup is documented. | Covers the founder's named harnesses with a cut order, and the founder's own Meta-model workflow from day one. | Founder |
| 22 | **The extension can do nothing the CLI refuses.** | One authority; the UI is not a bypass. | PRD |
| 23 | **Codictator writes no feature code.** Its own edits are generated guardrail files and mechanical dependency upgrades. | Keeps it a governor, not another agent to govern. | PRD |
| 24 | **Extension ships to the VS Code Marketplace and Open VSX.** | Cursor and other VS Code forks install from Open VSX. | PRD |
| 25 | **Architecture profiles: app (feature-based clean modular monolith, default), library, CLI, service**; boundaries within any profile are floor. | A sensible default for large apps without forcing one shape on every repo. | Founder |
| 26 | **The review gate is deterministic even though the reviewer is an LLM.** The gate checks a recorded fresh-session review bound to the exact diff, with zero open findings; it never parses the review's opinion as a pass. | Satisfies P1 while still requiring F11. | PRD |
| 27 | **MIT license; free and open source**, with no paid tier planned. | Adoption and trust for a tool installed into other people's repos. | Founder |
| 28 | **Dependency upgrades reuse existing bots.** Codictator generates Renovate or Dependabot config and reuses a bot already present; it owns the blocking verdict and opens upgrade PRs itself only when no bot is present (§7.5). | Renovate's maturity beats rebuilding it; the verdict is what bots lack. | Founder |
| 29 | **Users cannot widen tunable bounds.** Bounds are pack-owned; a wider bound needs a new pack version with a recorded reason (§6 P2). | A user-widened bound is a floor with an off switch. | Founder |
| 30 | **Meta-first.** Muse Code is the most important adapter — P0, best-supported, built and tested first, primary demo target. Muse models (Muse Spark 1.x, Muse Wonder; open-weight Muse Spark Open) are the default suggested provider for optional LLM features; Llama remains supported. | Founder priority. | Founder |
| 31 | **Removal is incremental and never breaks the app.** Everything unwanted in an existing repo (debt, vulnerable or outdated dependencies, bad structure, missing tests or docs) is removed step by step; each step is a small, separately verified change that keeps the build, tests and app working. A step that would break the app is split or sequenced behind a passing state, never forced through (§7.8, #13). | Forced cleanup that breaks the app gets Codictator uninstalled; steady, safe steps make the improvement relentless and survivable. | Founder |
| 32 | **Customisable and extensible.** Users integrate any external tool (linters, scanners, test runners, knowledge-base tools, token savers, bots) as an enforcer or helper, and add their own rules, packs, adapters and LLM providers, tighten tunables and customise the workflow. Limits: no floor rule weakened, no pack bound widened, everything visible and logged, new rules inert until their fixtures pass and a human accepts them. | Teams keep the tools they trust without opening a hole in the floor. | Founder |
| 33 | **Node.js LTS is a required runtime prerequisite in every target repo**, including .NET and Python repos; no standalone binary for now. | One runtime for every surface keeps the engine single and small. | Founder |
| 34 | **Ratchet on a touched file:** at least one of its ratcheted debt metrics must fall and none may rise; not every metric must fall. | Steady improvement without forcing a full cleanup of every legacy file an agent edits. | Founder |
| 35 | **A floor violation already on the default branch blocks every PR except one that fixes it**, and a commit missing the local-hook trailer blocks in CI unless its author is exempt. | No mercy on the floor and no silent `--no-verify`, without deadlocking the fix. | Founder |
| 36 | **Only GitHub Actions CI is generated in the first release**; GitLab and other hosts follow (§9.2), running the same one command meanwhile. | The git-host API also drives required-check and PR features; one host done fully beats several done partly. | Founder |
| 37 | **Names:** npm package and VS Code Marketplace / Open VSX publisher are both `codictator`. | One name everywhere. | Founder |
| 38 | **The Muse Code adapter ships with its hook layer marked unverified**: built on third-party evidence, `hookIoVerified` stays false until a first-party capture exists, and git hooks plus CI enforce meanwhile (§7.3). | The founder has no Muse Code access; waiting would stall the top-priority adapter, and the lower layers already enforce everything L1 might miss. | Founder |
